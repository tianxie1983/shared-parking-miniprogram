# 微信小程序虚拟支付（个人）开通与配置指南

> 适用对象：`共享停车小程序-微信支付版`（`miniprogram/` 前端 + `server/` 后端）
> 目标：把预约停车的支付，从「演示模式」切换为微信官方 **小程序虚拟支付（个人）** 真实收款
> 最后核对：2026-10-09（微信已于 2026-08-31 官方开放「虚拟支付：个人」能力）

---

## 一、先确认这是不是你想要的

微信小程序虚拟支付是**微信平台官方能力**，前端就一个 API：`wx.requestVirtualPayment`。本项目的代码已经在用它（不是自建、不是第三方），后端 `server.js` 也按官方规范算签名。

你要补的只是**微信侧的真实资质与密钥**——这正是下面这份清单要做的。

| 对比 | 普通微信支付 `wx.requestPayment` | 小程序虚拟支付 `wx.requestVirtualPayment` |
|---|---|---|
| 适用商品 | 实物 / 线下服务 | 虚拟商品 / 虚拟服务（无物流） |
| 个人主体 | ❌ 完全不能开 | ✅ 2026-08-31 起可开（仅限工具类目） |
| 企业/个体户 | ✅ | ✅（全品类） |
| 主要接口 | `wx.requestPayment` | `wx.requestVirtualPayment` |

本项目已经用的是右边的方案。

---

## 二、类目自查（决定你能不能开）

**个人主体开通虚拟支付有硬性门槛，缺一不可：**

| 条件 | 要求 | 共享停车自查 |
|---|---|---|
| 主体类型 | 个人主体（持中国大陆身份证） | ✅ 个人小程序即可 |
| 服务类目 | **必须包含「工具」类目**（工具-实用工具 / 工具-信息查询 / 工具-预约报名 等） | ⚠️ 共享停车可归到 **工具-预约/报名**（预约车位时段使用权 = 预约服务），需在 MP 后台把类目设对 |
| 认证 | 完成小程序个人认证（30 元/年） | 需自查是否已认证 |
| 备案 | 完成 ICP 备案（个人小程序必备，未备案无开通入口） | 需自查是否已备案 |

> 💡 **关于"免费"的说明（重要，避免误解）**
> 微信官方开放的「小程序虚拟支付：个人」能力，**开通本身 0 开通费、0 年费**——外界说的"免费"指的就是这一层。
> 上表三项（类目含工具 / 个人认证 30元·年 / ICP 备案）**不是虚拟支付单独收的费**，而是**个人小程序能上线、能进「支付与交易」后台的既有基础要求**（认证费是小程序认证费、备案是上线必备）。虚拟支付只是建在这之上的一个开关，开通它"必须已经满足"这些前置条件，但不需要为这个开关本身再交钱。
> 真正产生费用的是**交易费率**：Android 约 1%（限时优惠，标准 10%）、iOS 约 12%~13%（苹果佣金）。

**自查清单（逐项打勾）：**
- [ ] 小程序主体是「个人」而非企业/个体户
- [ ] 服务类目已添加「工具」相关二级类目，且实际功能与之匹配（代码审核会核查，别乱选）
- [ ] 已完成个人认证（设置 → 小程序信息 → 认证）
- [ ] 已完成 ICP 备案（开发管理 → 备案）
- [ ] 账号无违规 / 封禁记录

> ⚠️ **类目判定风险**：共享停车若被判定为「电商交易 / 线下核销 / 实物服务」则不在工具类范围内，可能驳回。
> 申诉理由建议写成「车位时段预约信息服务（工具-预约/报名）」，强调是**虚拟预约服务、无实物交付、无物流**。
> 若长期商业化、流水超月限额，建议升级为个体工商户主体（可走全品类 + 标准微信支付，无 10 万月限额）。

## 三、MP 后台开通流程（约 5 分钟审核）

1. 登录 [微信公众平台 mp.weixin.qq.com](https://mp.weixin.qq.com)，进入你的个人小程序后台。
2. 左侧菜单 **支付与交易 → 虚拟支付**，点 **开通 / 立即开通**。
3. 勾选《虚拟支付服务协议》，下一步。
4. 填写资料：
   - 个人实名信息（自动回填，核对即可）
   - 提现银行卡（**本人名下储蓄卡**，姓名/卡号/开户行务必一致；提交后不可改，首笔交易会打 0.01 元验证）
   - 支付管理员（个人主体默认本人，可跳过验证）
5. 提交 → 一般 **5 分钟内** 出审核结果。
6. 审核通过后，**微信扫码签约**，即开通完成。

开通后后台出现完整的「虚拟支付」商户模块（资金管理 / 交易订单 / 基本配置）。

## 四、获取关键凭证

开通并签约后，到 **虚拟支付 → 基本配置** 拿：

| 参数 | 说明 | 在 MP 后台位置 | 本项目用途 |
|---|---|---|---|
| `AppID` | 小程序 ID | 设置 → 基本设置 | 已在小程序端 `app.js` |
| `OfferID` | 支付应用 ID（你的支付账号） | 虚拟支付 → 基本配置 | 后端 `vpay.offerId` |
| `现网 AppKey` | 支付密钥，**只在服务端用**，绝不能进前端代码 | 虚拟支付 → 基本配置 | 后端 `vpay.appKeyProd` |
| `沙箱 AppKey` | 沙箱环境密钥（env=1 时用） | 虚拟支付 → 基本配置 | 后端 `vpay.appKeySandbox` |

## 五、创建「停车币」代币道具（本项目采用代币模式）

> **本项目已落地「代币充值模式 short_series_coin」**（即下方方案 A），这是默认实现，不是待办。

停车费属于「高频、多次、小额消费」，按微信官方接入指引优先采用**代币模式**：

- 在米大师建一个固定面额的「停车币」代币道具（如单价 ¥1/枚，对应一个固定 `coinProductId`）。
- 用户先充值停车币（走真实虚拟支付），余额存在后端账户。
- 预约停车时**扣后端余额**，不再每笔调微信支付。
- 真实收款只发生在「充值」这一步，且金额固定匹配代币 → 完全合规（停车币属于虚拟商品）。

**为什么不用道具直购（short_series_goods）？**
道具直购要求 `productId` 在米大师后台的**价格固定**，但每笔停车订单金额是动态的（不同车位/时段），
若把 `goodsPrice` 设为动态订单金额，真实环境会因价格不一致下单失败。代币模式从根本上规避了这个问题。

到 **虚拟支付 → 道具管理 / 代币配置** 创建「停车币」代币道具，发布到现网（约 10 分钟后生效），拿到 `coinProductId`；
代币兑换比例（每枚单价）由 `VPAY_COIN_UNIT_PRICE_FEN` 决定（默认 100 = ¥1/枚）。

## 六、把凭证填入后端配置

把第四章拿到的凭证，填进后端 `server/` 同目录的 `config.json`（参考 `config.example.json`）：

```json
{
  "appid": "wx你的小程序AppID",
  "secret": "你的小程序AppSecret",
  "vpay": {
    "offerId": "在「虚拟支付→基本配置」拿到的 OfferID",
    "appKeyProd": "现网 AppKey",
    "appKeySandbox": "沙箱 AppKey（env=1 时用，可先空着）",
    "coinProductId": "「停车币」代币道具 ID",
    "coinUnitPriceFen": 100,
    "env": 0
  }
}
```

字段说明（与 `server.js` 顶部读取逻辑一一对应）：

| config.json 字段 | 环境变量（部署时用，优先级更高） | 含义 |
|---|---|---|
| `vpay.offerId` | `VPAY_OFFER_ID` | 支付应用 ID |
| `vpay.appKeyProd` | `VPAY_APPKEY_PROD` | 现网 AppKey（真实交易用） |
| `vpay.appKeySandbox` | `VPAY_APPKEY_SANDBOX` | 沙箱 AppKey |
| `vpay.coinProductId` | `VPAY_COIN_PRODUCT_ID` | 停车币代币道具 ID |
| `vpay.coinUnitPriceFen` | `VPAY_COIN_UNIT_PRICE_FEN` | 每枚单价（分），默认 100（¥1/枚） |
| `vpay.env` | `VPAY_ENV` | `0`=正式环境（个人主体固定 0），`1`=沙箱 |

> 后端优先级：环境变量 > `config.json` > 空（空则走 mock 演示模式）。
> `currencyType` 当前在代码里固定为 `CNY`，无需配置。

## 七、小程序端配置（两个必做）

1. **request 合法域名**：把后端公网地址加入小程序 **request 合法域名**。
   - 开发期可临时勾选「不校验合法域名」；上线前必须加。
   - 部署后，把 `miniprogram/utils/api.js` 的 `BASE_URL`（与 `app.js` 的 `globalData.baseUrl`）改成公网地址。

2. **虚拟支付回调地址（发货推送 URL）**：
   - MP 后台 **虚拟支付 → 基本配置 → 发货推送 URL** 填：`https://<你的后端公网地址>/order/virtual-pay-notify`
   - 必须 HTTPS。
   - 后端 `/order/virtual-pay-notify` 已实现对「停车币充值单（outTradeNo 以 `CR` 开头）」的入账（幂等）。

## 八、当前代码对接点 & 验证状态

**前端**（已对接官方 API，无需改动即可真实收款）：
- `pages/wallet/wallet.js`：充值页，调 `POST /wallet/recharge` 拿到签名参数后调起
  `wx.requestVirtualPayment({ mode:'short_series_coin', signData, paySig, signature })`；
  `success` 后调 `POST /wallet/client-confirm` 主动确认入账（兜底回调延迟）。
- `pages/booking/booking.js` / `pages/order/order.js`：支付时调 `POST /order/pay` 从钱包余额扣减；
  余额不足（`code:-2`）提示去充值。
- 未配密钥时 `/wallet/recharge` 返回 `mock:true`，前端自动走「演示」并直接入账，可完整体验闭环。

**后端**（`server.js`）：
- 读取 VPAY 配置（环境变量 / `config.json`）。
- `POST /wallet/recharge`：组装 `short_series_coin` 的 `signData`（offerId/buyQuantity/env/currencyType/outTradeNo/attach）
  + `paySig` + `signature`；未配置返回 `mock:true` 直接入账。
- `POST /wallet/client-confirm`：前端确认入账（幂等）。
- `POST /order/pay`：从钱包余额扣减（停车费 + 占座诚意金），不足返回 `-2`。
- `POST /order/virtual-pay-notify`：微信异步回调，处理 `CR...` 充值单入账（幂等）。
- 登录时保存 `sessionKey` 供用户态签名 `signature`。

**已验证（本地端到端测试）**：
- `node --check` 语法全过。
- 完整闭环：找车位 → 充值 → 余额正确增加 → 创建订单 → 余额扣减 → 余额不足返回 `-2` → 重复支付/重复确认幂等 → 微信回调幂等，全部通过。
- 真实签名路径：返回正确 64 位 `paySig` / `signature`，字段与微信官方规范一致
  （HMAC-SHA256：`paySig=hmac(appKey,'requestVirtualPayment&'+signData)`，`signature=hmac(sessionKey,signData)`）。

## 九、上线前必做（查单兜底与验签）

生产环境应以微信异步推送 `/order/virtual-pay-notify` 为准，并补充：
- **验签**：回调需校验微信推送签名，拒绝伪造请求。
- **查单兜底（query_order）+ 幂等（按 outTradeNo 去重）**：防丢推送导致重复/漏发货。
- 本项目回调为可上线骨架（已按 `CR` 前缀幂等入账），上线前请补完验签与查单。

## 十、常见避坑

1. **模拟器无法真实交易**：`wx.requestVirtualPayment` 仅在**安卓 / iOS 真机（或真机调试）**生效，开发者工具模拟器调不起真实支付。调试可用 mock 模式。
2. **签名 90010 错误**：`signData` 字符串必须与前后端**逐字符一致**（字段顺序、空格、无多余转义）。本项目由后端统一生成并原样返回，已规避此坑，但**改代码时别动 signData 结构**。
3. **env 固定 0**：个人主体接入指引要求 `env=0`（现网），否则金额/费率不对。
4. **发货不以前端 success 为准**：生产环境应以微信异步推送 `/order/virtual-pay-notify` 为准，并做**查单兜底 + 幂等**，防丢推送导致重复/漏发货。
5. **严禁前端生成签名/订单**：AppKey、sessionKey 绝不能出现在小程序前端代码，本项目签名全在后端，符合要求。
6. **费率与限额**：Android 端约 1%（2026 限时优惠，标准 10%），iOS 端 12%（苹果税）；个人主体**月限额 10 万元**；结算 T+3。
7. **不要卖实物**：虚拟支付严禁实物/线下交易，违规会关支付权限。
