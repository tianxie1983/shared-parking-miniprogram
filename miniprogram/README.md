/**
 * 邻里共享停车 - 微信小程序（用户纯享版）
 *
 * 基于《邻里共享停车MVP技术实现方案》V2.0
 * 本版本为纯用户端，不含商户管理功能，不含任何示例/演示数据。
 *
 * ============================================================
 * 与混合版的区别：
 *   - 移除角色切换（用户/商户），仅保留用户模式
 *   - 移除审核管理、收益统计等商户专属页面
 *   - 保留发布车位和我的车位功能（用户既是车位租客也是车位提供者）
 *   - TabBar 4个Tab：找车位/订单/发布/我的
 *   - 移除所有示例数据（车位、订单、信用记录、投诉均为空）
 *   - 用户发布车位后自动审核通过（用户版无管理端）
 *   - 用户初始状态为未认证，需自行完成实名认证
 *
 * ============================================================
 * 核心功能：
 *   1. 找车位：LBS定位 + 车位列表/地图切换 + 筛选（价格/距离/认证）
 *   2. 搜索：按小区名/地址/标签搜索车位
 *   3. 车位详情：照片/标签/时段/评分/预约入口
 *   4. 预约支付：选时段 → 创建订单 → 支付 → 双重确认轮询
 *   5. 订单管理：列表（状态Tab切换）+ 详情（状态机驱动）
 *   6. 入场/离场：远程开闸 + 超时检测 + 双倍计费
 *   7. 信用系统：信用分展示 + 扣分记录 + 阈值规则
 *   8. 投诉纠纷：投诉提交 + 关联订单状态变更
 *   9. 实名认证：姓名+身份证认证 + 手机号绑定
 *  10. 发布车位：填写信息+地图选址+上传照片+设置时段价格
 *  11. 我的车位：查看已发布车位状态+上架/下架管理
 *  12. 帮助/关于：使用帮助 + 关于我们
 *
 * ============================================================
 * 方案核心设计要点在代码中的实现映射：
 *
 * 1. 支付-离场高可用闭环（方案6.2）
 *    → booking.js: _onPaySuccess() 支付后的双重确认机制
 *    → booking.js: _startPolling() 前端轮询（每3秒×20次=60秒）
 *    → order.js: onConfirmEnter/Exit() 远程开闸
 *    → mock.js: POST:/order/exit 模拟超时检测和双倍计费
 *
 * 2. 车位状态缓存与分布式锁（方案2.2）
 *    → mock.js: POST:/order/create 模拟冲突检测
 *    → booking.js: onPayTap() 订单创建前检查
 *
 * 3. 超时预警与违约约束（方案6.1）
 *    → order.js: _checkOvertime() 超时检测（距结束<15分钟预警）
 *    → order.wxml: 超时警告UI（黄色/红色提示）
 *    → credit.wxml: 信用扣分规则展示
 *    → app.js: _checkPendingOrder() 全局超时检查
 *
 * 4. 硬件统一适配层（方案6.3）
 *    → order.js: onConfirmEnter/Exit() 统一开闸接口
 *
 * 5. 信用评分系统（方案6.5）
 *    → mine.wxml: 信用分展示 + 阈值规则（<60限制预约/<40冻结）
 *    → credit.wxml: 信用分详情 + 扣分记录
 *    → 信用分初始100，规则参考方案表格15
 *
 * 6. 订单状态机（方案6.1）
 *    → order.js: ORDER_STATUS 状态映射
 *    → orders.js: STATUS_MAP 状态标签
 *    → order.wxml: 各状态对应UI和操作按钮
 *    → 状态流转：待支付→待入场→停车中→已完成/已取消/争议中
 *
 * 7. 保险与纠纷入口（方案6.6）
 *    → complaint.wxml/js: 投诉提交流程
 *    → order.wxml: 已完成/争议中订单的投诉按钮
 *
 * 8. 车位发布与地图选址
 *    → publish.js: wx.chooseLocation 地图选址 + 照片上传 + 时段价格设置
 *    → publish.wxml: 表单验证 + 实名认证前置检查
 *    → my-spaces.js: 查看已发布车位 + 上架/下架切换
 *    → mock.js: POST:/parking/publish 发布后自动审核通过
 *
 * ============================================================
 * 目录结构：
 *   pages/             - 14个页面
 *     index/           - 首页（LBS车位浏览+地图）
 *     search/          - 搜索页
 *     parking-detail/  - 车位详情
 *     booking/         - 预约+支付（含双重确认轮询）
 *     order/           - 订单详情+状态机
 *     orders/          - 订单列表（Tab切换）
 *     publish/         - 发布车位（地图选址+上传照片+时段价格）
 *     my-spaces/       - 我的车位管理（查看状态+上架/下架）
 *     mine/            - 个人中心
 *     auth/            - 实名认证
 *     credit/          - 信用评分
 *     complaint/       - 投诉纠纷
 *     help/            - 帮助与反馈
 *     about/           - 关于我们
 *   components/        - 复用组件（parking-card, empty-state）
 *   styles/            - 共享样式（form.wxss）
 *   utils/             - 工具层
 *     api.js           - 请求封装+Mock拦截
 *     auth.js          - 认证工具
 *     mock.js          - Mock数据层（模拟后端API，无示例数据，含发布/管理车位API）
 *
 * ============================================================
 * 使用方法：
 *   1. 微信开发者工具打开此目录
 *   2. 修改 project.config.json 中的 appid 为你的小程序AppID
 *   3. Mock模式：utils/api.js 中 USE_MOCK = true（默认）
 *   4. 上线前：USE_MOCK = false，配置 baseUrl 为实际API地址
 *
 * 后端对接：
 *   - Spring Boot API（/v1/*）
 *   - MySQL 数据库设计参考方案第四章
 *   - Redis 缓存车位状态
 *   - 消息队列异步通知
 *
 * 注意：
 *   - tab bar 图标文件（images/*.png）需自行准备
 *   - 地图 marker 图标需自行准备
 *   - 项目使用微信原生框架，无需构建工具
 *   - 所有列表初始为空，数据由后端API或用户操作产生
 */
